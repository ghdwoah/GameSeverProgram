## 예측과 보정이 돌아가는 순서

```
키를 누름
  │
  ├─ 1. 서버로 보냄                  MOVE|3|152|1|0
  ├─ 2. _pendingInputs 에 적어둠      (152, +1, 0)
  └─ 3. 화면을 먼저 움직임            StepGrid(...)   ← 예측

   ... 왕복 시간 ...

STATE|149|... 도착
  │
  ├─ 1. 149 이하 입력을 목록에서 지움
  ├─ 2. 서버가 준 좌표에서 출발         ← 서버가 진실
  └─ 3. 남은 입력(150~152)을 다시 적용   ← 보정
```

3번에서 결과가 지금 화면과 같으면 아무 일도 안 일어납니다.
다르면 좌표가 바뀝니다. 그게 **고무줄 현상**입니다.

왜 서버 좌표로 그냥 덮지 않는가 — 서버 좌표는 왕복 시간만큼
과거입니다. 그대로 쓰면 캐릭터가 뒤로 끌려갑니다.

## 조작

```
W A S D  또는 방향키     이동 (방향만 전송)
P                        예측 끄기 / 켜기
R                        재시작 · 재접속
ESC                      종료
```

`P` 로 예측을 끄면 서버 답을 기다리는 동작이 됩니다.
로컬에서는 차이가 작지만, 서버를 다른 PC 에 두면 확실히 느껴집니다.
지연을 직접 넣어보려면 **예제 H(Prediction)** 를 쓰세요.

## 왼쪽 아래 표시 읽는 법

```
예측 ON    확인 안 됨 2    보정 0회    서버 확인 번호 152
                    │            │
       서버 답을 기다리는 입력 수   예측이 틀린 횟수
```

| | 정상 | 이상하면 |
|---|---|---|
| 확인 안 됨 | 0~3 | 계속 올라가면 서버가 AckSeq 를 안 보내는 중 |
| 보정 | 0 근처 | 계속 올라가면 `StepGrid` 가 서버와 다름 |
| 서버 확인 번호 | 올라감 | 0 에서 멈추면 서버 TODO 5 누락 |

## 다른 사람 캐릭터는 보간입니다

내 캐릭터는 **예측**, 다른 사람은 **보간** 입니다.

```
내 캐릭터    내 입력을 내가 아니까 예측할 수 있습니다
남의 캐릭터  뭘 누를지 모르니 예측할 수 없습니다
             → 받은 위치로 부드럽게 따라가게만 합니다 (Vector3.Lerp)
```

서버는 초당 30번만 알려줍니다. 받은 자리로 순간이동시키면
뚝뚝 끊겨 보입니다. 그래서 `InterpolateRemotes()` 가 나눠서 움직입니다.

## 꼭 맞춰야 하는 숫자

```
맵 크기                     가로 20 · 세로 12
GameConfig.MOVE_COOLDOWN  =  0.132초
서버 GameLoop.STEP_TICKS  =  4틱  (4 x 33ms = 132ms)
```

걸음 간격이 다르면

- 클라가 더 빠르면 → 입력이 서버 버퍼에 쌓여 조작이 밀립니다
- 클라가 더 느리면 → 손해만 봅니다

## 키를 눌렀는데 안 움직이면

예측이 켜져 있으면 **화면은 무조건 움직입니다.** 그런데 곧 제자리로
끌려오면 서버가 입력을 안 받아주고 있는 것입니다.

```
1. 서버가 떠 있는지
2. 서버 콘솔의 '입력' 숫자가 올라가는지     → 안 오르면 TODO 1
3. '거부' 나 '폐기' 숫자가 오르는지          → 오르면 검증에 걸린 것
4. '서버 확인 번호' 가 0 인지                → 0 이면 TODO 5
```
