# 6주차 실습 — TICKET-021 서버가 심판이 된다

## 오늘 바뀌는 것

```
5주차   MOVE|3|152|10|7      클라가 "나 (10,7)에 있어"
6주차   MOVE|3|152|1|0       클라가 "오른쪽으로 갈래"
                             좌표는 서버가 계산
```

좌표를 보내면 서버는 받아 적을 수밖에 없습니다.
방향만 보내면 **판정권이 서버로 넘어옵니다.**

오늘 서버가 이 일들을 하게 만듭니다.

```
좌표 계산      방향을 받아서 직접 계산
아이템 스폰    어디에 생길지 서버가 결정
획득 판정      거리를 재서 서버가 판정
점수 집계      서버가 세고 알려줌
```

---

## 그런데 방향만 받는 걸로는 부족합니다

이건 막힙니다.

```
MOVE|3|152|20|0      DX 가 20 → 한 걸음 거리가 아님
```

이건 안 막힙니다.

```
MOVE|3|152|1|0
MOVE|3|153|1|0
MOVE|3|154|1|0       ... DX=1 을 1초에 300번
```

거리를 어긴 게 아니라 **횟수**로 속도를 올렸습니다.
규칙은 하나도 안 어겼는데 결과는 순간이동과 같습니다.

| | 맵 가로 20칸을 건너는 시간 |
|---|---|
| 정상 클라이언트 | 2.5초 |
| 패킷만 많이 보내면 | **0.03초** |

검사를 하나 더 넣어서 막는 문제가 아닙니다.

```
좌표를 보냄    서버가 위치를 안 가짐   →  순간이동
명령을 보냄    서버가 시계를 안 가짐   →  속도핵
틱이 꺼내 씀   서버가 둘 다 가짐       →  막힘     ← 오늘 만드는 것
```

서버가 **자기 시계로 꺼내 쓰면** 클라가 몇 개를 보내든 속도가 같습니다.

---

## 그 대가 — 조작이 무거워집니다

판정을 전부 서버로 옮기면 내 입력도 왕복을 기다려야 합니다.

```
키를 누름 → 서버로 보냄 → 서버가 계산 → STATE 로 받음 → 화면
            └────────── 왕복 시간 ──────────┘

로컬          1ms 미만        안 느껴집니다
같은 나라     20 ~ 50ms       약간 무겁습니다
해외 서버     150 ~ 250ms     "조작이 안 먹는다" 는 말이 나옵니다
```

왕복 시간은 물리적으로 못 줄입니다. 그래서 **없애는 게 아니라 숨깁니다.**
그게 오늘 후반부의 클라이언트 예측입니다.

## 예제 H — 예측과 보정 실험실

네트워크를 쓰지 않습니다. 한 프로그램 안에 클라이언트와 서버가 같이 들어 있고,
그 사이에 **일부러 지연시키는 큐**를 놓았습니다. 그래서 지연을 마음대로 바꿀 수 있습니다.

```
A / D       한 걸음 이동
G           오른쪽으로 2초간 자동 질주
P           예측 켜기 / 끄기
R           클라이언트도 벽을 알게 하기
+ / -       지연 조절 (0 ~ 400ms)
Q           종료
```

맵 가운데 `#` 는 벽입니다. **서버만 벽을 알고 있습니다.**

### 해볼 것

1. 지연 150ms, `P` 로 예측을 꺼 보세요 → 키를 눌러도 늦게 움직입니다
2. 예측을 켜고 `G` → 예측이 벽을 통과했다가 끌려옵니다 (고무줄)
3. `R` 로 클라이언트도 벽을 알게 하고 `G` → 보정이 0 으로 멈춥니다

**3번이 오늘의 결론입니다.** 예측은 서버와 같은 규칙으로 계산해야 맞습니다.
규칙이 다르면 예측이 아니라 추측이고, 화면이 자꾸 튑니다.

## 통신 규약

### UDP 7778 — 조작과 상태

```
클라 → 서버   MOVE|플레이어ID|시퀀스|DX|DY
              예) MOVE|3|152|1|0        오른쪽으로 한 칸

서버 → 클라   STATE|AckSeq|id,닉네임,x,y|...
              ITEMS|아이템id,x,y|...
```

DX, DY 는 **-1, 0, 1** 만 허용합니다. 그 외는 전부 거부합니다.

`AckSeq` 는 **"네가 보낸 152번까지 반영했다"** 는 영수증입니다.
사람 목록은 모두에게 같지만 이 번호는 받는 사람마다 다릅니다.
클라이언트는 이 번호로 자기 예측을 맞춰봅니다.

### TCP 7777 — 놓치면 안 되는 것

| Type | 내용 |
|---|---|
| 30 | 누가 아이템을 먹었다 |
| 31 | 점수판 |

**왜 아이템 위치는 UDP 인데 획득 알림은 TCP 일까요?**
이 질문에 답할 수 있어야 합니다.
